CURRENT SCOPE
Seven screen states: menu, background selection, companion naming, shop, travel, location, and ending; plus an event modal and HUD. Four backgrounds: influencer, developer, prepper, barista. Party size five. Route milestones: 0, 200, 350, 470, 670, 750, 1000 miles. Six shop categories: food, fuel, seed bombs, repair parts, kombucha, NFT. Nine configured random encounters, six auto, two choice, one critical. Save storage is localStorage. No server API, live model calls, multiplayer, audio, or actual sprite animation was found in the delivered files.

FIRST IMPLEMENTATION TARGET
Use the current Sites building and hosting skills available in the rebuild session. A browser game can initially be a static frontend with local, versioned saves. Choose a small, conventional app structure informed by the supplied vanilla export. A lightweight React/TypeScript implementation is one option, not an audit requirement. Complete one playable route and a dependable event loop before adding optional services or elaborate presentation.

Separate rules from rendering. Use serializable state with stable profession, location, item, and event ids. Event definitions can live in code; saved state must contain ids, pending choice, and RNG state where useful, not executable functions. Use one action transition to apply consequences, consume resources, update the journal, resolve arrivals and terminal conditions, and persist. Seeded randomness or injected RNG should support targeted tests. A modal pauses further turn advancement until it resolves exactly once. Terminal states cannot be changed by resting or another action.

Must address F01-F07 before cosmetic polish. New Game must not merge the previous save. Loss must stop turn processing. Death is permanent. Pace costs must be affordable before travel. Automatic and critical outcomes must update state, display and save together. Loading must restore a pending encounter and the correct location. Shops should return to their originating location. Render activities from the location data.

Balance the route deliberately. Every baseline pace consumes one fuel canister per ten miles, so a 1000-mile trip needs 100 canisters before event bonuses. At $60 per canister, no background can buy enough fuel solely from its initial fuel and cash, even before buying food. This is a budget check, not a measured impossibility result: random supplies, extra-distance events and NFT sales can change the run. Choose reliable resupply / income / route costs and simulate a small number of seeded runs. Rest and forage need a clear cost. Implement profession abilities that are advertised, or revise the descriptions. Seed bombs and kombucha need usable actions if they remain in the store.

Build editable titles and readable labels in the UI rather than baking them into generated images. Keep the same van, traveler proportions, outlines, palette, and camera conventions throughout the art.

Distinguish a nonterminal setback from an ending illustration. Verify scene content visually rather than by filename alone.

On desktop, present a compact play area with scene, route progress, resource counts, party status, journal and clear actions. On phone, prioritize current scene, essential status, next stop, and a reachable Continue action. Shorten visible location labels while retaining full names in narrative text. Fix companion-name rows at 430 px; prevent horizontal clipping. Avoid the current 50vh bottom-padding workaround. Use responsive status layout rather than an oversized HUD covering the scene. Give small quantity controls useful touch targets. Background choices and event dialogs must be keyboard-accessible, with visible focus and appropriate focus management.

MINIMUM ACCEPTANCE CHECKS
1. New Game resets distance, day, party, inventory, flags, pending events and journal.
2. All four backgrounds start with their declared resources and any advertised ability works.
3. Purchases cannot overspend; resource costs cannot produce negative inventory.
4. Auto, choice and critical encounters resolve exactly once; a pending encounter survives reload.
5. HUD, scene, progress, log and saved state agree after every action.
6. Dead travelers remain dead. Rest and forage obey their defined costs.
7. Arrival and event bonuses can trigger an immediate win or loss appropriately.
8. Location activities follow location data; leaving a location shop restores that location.
9. Win and loss have distinct correct art and a functioning replay action.
10. All essential controls remain visible / reachable at 390, 414, 430, 768 and 1440 px. Check Safari on a real phone when available.
11. Keyboard-only background selection and event choices work; dialog focus is handled.
12. One complete route is playable with deliberate, validated balance; preserve at least one seeded successful and one seeded losing run as evidence.
